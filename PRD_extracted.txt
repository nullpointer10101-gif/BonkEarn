1. Executive Summary
BonkHub is a Telegram Mini App that rewards users with BONK tokens for watching advertisements, completing social tasks, and referring new users. The product is inspired by viral Telegram reward bots and improves on them with robust anti-fraud infrastructure, automated ad verification, a tiered referral system, and a semi-automated withdrawal pipeline.
The goal is to build a high-retention, viral-growth platform that drives BONK token adoption while monetising through ad network revenue.

2. Goals & Success Metrics
2.1 Business Goals
Drive BONK token adoption via daily active engagement
Monetise via ad network revenue (Adsgram / Monetag)
Achieve viral growth through referral mechanics

4.2 Authentication
All Mini App requests authenticated via Telegram initData HMAC-SHA256 validation
Server MUST verify initData hash on every API request — never trust client-supplied user_id
Session tokens: short-lived JWT (1h) + refresh token (7d) stored server-side
No passwords — Telegram identity is the sole auth source

8. Anti-Fraud & Security


Threat
Mitigation
Fake ad views (bot clicking)
Server-side ad network callback required before step 2 unlock. No callback = no reward.
Multiple accounts (same user)
TG user_id is primary identity. Cross-check device fingerprint where possible.
Fake referrals (self-referral)
Block if referrer_id == user_id. Flag accounts with >10 referrals in <1h.
Referral farming (fresh accounts)
New TG accounts <7 days old = flagged referral, not counted as verified ref.
Task re-claiming
Unique constraint on task_completions(user_id, task_id). Server-side idempotency check.
Withdrawal address injection
Validate Solana address format server-side (base58, 32-44 chars). Reject otherwise.
Replay attacks on /ads/callback
Verify HMAC signature from ad network on every callback. One-time nonce per session.
Balance manipulation
Balance only modified via server-side credited transactions. No client-supplied balance field accepted.
Admin endpoint exposure
Admin routes protected by separate admin JWT. Admin accounts hardcoded/seeded, no self-registration.
Rate limiting
Redis-based: 30 req/min per user globally. /ads/start: 1 per 30s. /withdraw/request: 1 per hour.
